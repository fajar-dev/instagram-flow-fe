## Follow-up: typography, tables and request lifecycle

Reference screens: contact, user and profile. The actual theme in `app.config.ts` and `main.css` remains authoritative; no palette or dependency changes were needed.

- Dashboard body text now explicitly uses `text-sm`, matching table/form text. Section headings use `text-base font-semibold`, secondary identifiers `text-xs text-muted`, and overview metrics `text-2xl tabular-nums`. Page headings continue using `Header`.
- Jobs, review queue and activity logs reuse `DataTable` instead of a separate stack of cards. The media grid uses its new `content` slot, sharing search, page-size options and pagination. Gallery actions use the compact `xs` sizing already used by profile photo actions. Long technical hashes were removed from the gallery display; API fields are unchanged.
- Upload and integration settings use the profile form width (`max-w-2xl`), normal spacing and consistent label/value typography. Existing brand colors and avatar behavior are preserved.
- `useLatestRequest` centralizes loading, failure and latest-response handling for contact/user lists, reporting, overview, job detail and settings. Superseded responses/errors and completions after unmount cannot update the view or show a toast.
- Changing page size/sort resets pagination to page one; list refresh after deletion/archive clamps an invalid page to the last available page. Reporting sends the selected page size to the API and uses its range metadata.
- Overview, job detail, settings and studio now distinguish loading/failure from empty/not-ready data. Settings applies the actual saved response and prevents duplicate saves; upload metadata and removal controls are disabled during submission. Dynamic job/studio routes have explicit page keys so navigation to another job recreates the detail state.
- Activity logs render the existing forbidden state for roles that cannot read logs, instead of starting repeated failing polling requests.

Regression tests cover latest-response races, obsolete failures, unmount behavior, page-size and sort resets. Browser verification remains unavailable, so spacing and responsive changes are verified from source/typecheck/build, not claimed as visually tested.

Verification for this follow-up: frontend **27 tests passed / 120 assertions**, full ESLint, Nuxt typecheck and production build passed. Both locales contain **363 matching keys**. Backend **146 tests passed / 670 assertions**, typecheck and build passed. Git whitespace checks passed in both repositories. Existing third-party Rollup annotation warnings do not fail the frontend build. No browser UAT is claimed.

## Follow-up: remove manual refresh controls

- Removed every refresh/reload button from reporting lists, overview, job detail, integration settings and studio, including error-alert actions. Removed unused translation keys and empty table action containers.
- Data loading remains on mount, query/filter changes, successful mutations and the existing polling on overview/job/list screens. Auth token refresh is unrelated and remains intact. Studio is not automatically reloaded while editing, preventing silent loss of unsaved changes.
- Reporting now reuses `useTableQuery` for page size, pagination and debounced search, removing duplicated watcher/timer logic. DataTable owns the single default page-size option list.
- Repeated failed polling now keeps an error state with one toast per failure period; a successful request clears the state so a later failure can be reported again. A regression test covers failure/recovery/failure.
